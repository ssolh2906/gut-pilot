# G10 — Prevalence filter

> Removing them costs little and relaxes the correction, which is exactly why the setting
> needs watching.

The only gate that gets *more* significant results as you filter harder, and the only one with a
rule about **when** it was changed rather than what it was changed to.

---

## 1. Anchor

`#gatePrev` · Differential page · `renderPrev()`

Sub-elements: `#prevOpts` (four options), `#prevNote`. Downstream: `#volcanoChart`, `#ktBody`,
`#pitList`.

## 2. Layer

| Field | Layer | Note |
|---|---|---|
| `n_tested`, `dropped[]`, `n_significant` | Compute | |
| `recommendation` | Reasoning | "RECOMMENDS 10%" |
| `note`, thresholds | Evidence (T24) | |
| `forking_paths` | Evidence (T29) | Rule, not a judgement call |

## 3. Endpoint

`GET  /api/session/{sid}/da/prevalence`
`POST /api/session/{sid}/da/prevalence` — `{ "threshold": 0.10 }`

## 4. Request

Depends on: **G4** (total feature count), **G7** (retained samples define prevalence).
Feeds **G8** (`n_tested` sets correction stringency).

## 5. Response

```json
{
  "gate_id": "G10",
  "threshold": 0.10,
  "recommendation": { "threshold": 0.10, "label": "RECOMMENDS 10%" },
  "options": [
    { "value": 0.00, "label": "No filter", "sub": "Keep every feature", "n_tested": 187 },
    { "value": 0.05, "label": "5%",  "sub": "Permissive",  "n_tested": 174 },
    { "value": 0.10, "label": "10%", "sub": "Recommended", "n_tested": 160, "default": true },
    { "value": 0.20, "label": "20%", "sub": "Strict",      "n_tested": 131 }
  ],
  "result": {
    "n_tested": 160,
    "n_total": 187,
    "dropped_named_taxa": ["Solobacterium"],
    "n_significant": 5
  },
  "note": {
    "severity": "info",
    "message": "Filtering to features present in at least 10% of samples leaves 160 of 187 features. Named taxa removed: Solobacterium. Fewer tests means a less stringent correction, so the significant count can rise as you filter harder."
  },
  "forking_paths": { "fired": false }
}
```

**`n_tested` on every option, not just the selected one.** The gate's counter-intuitive property —
filtering harder can *increase* significant hits — is only visible if the reviewer can see the
denominators side by side before choosing.

With **R6** fired:

```json
{
  "forking_paths": {
    "fired": true,
    "rule": "R6",
    "severity": "warn",
    "results_viewed_at": "2026-08-15T11:04:22Z",
    "changed_at": "2026-08-15T11:09:47Z",
    "message": "You changed this after seeing the results. Tuning a prevalence filter until the hit list improves is a garden-of-forking-paths problem: the reported q-values no longer account for the choices you made to reach them. If you keep this setting, say in the methods that it was chosen post hoc."
  }
}
```

## 6. Invalidation

| Target | Effect |
|---|---|
| `da.volcano` | features enter or leave the plot |
| `da.known_taxa` | dropped taxa become `NOT TESTED` |
| `warnings.P4` | Solobacterium's artifact warning depends on whether it survives the filter |
| **G8** `n_tested` | correction denominator changes, so every q changes |

Cheap arithmetic, wide blast radius. Nothing re-rarefies.

## 7. Evidence

| Table | Supplies | Status |
|---|---|---|
| **T24** Prevalence filter conventions | the four presets, labels, sources, dataset type | Not built |
| **T29** Analytic-flexibility rules | R6 trigger and wording, source | Not built |

**T29 is currently uncited.** The forking-paths argument is a real and well-known one (Gelman &
Loken), but the mock states it with no reference while citing everything else. It is the one place
the product does what it criticises.

## 8. States

| Condition | Behaviour |
|---|---|
| `threshold = 0` | No filter. Note should still warn that untested rare features inflate the correction |
| `n_tested = 0` | Block. G8 cannot divide by zero |
| G1 = single-cohort | DA does not run; gate is recorded for reproducibility but has no result |
| `dropped_named_taxa` non-empty | Name them. "Named taxa removed: Solobacterium" is the honest form — a count alone hides which finding vanished |

**R6 timing.** `results_viewed` is set the first time the volcano renders (`daViewed = true` in the
mock). R6 fires when the threshold changes *after* that timestamp **and** differs from the
recommended 0.10. Returning to 0.10 clears the flag; any other post-hoc value keeps it.

## 9. Decision log

Recorded **on click**, keyed `g10`.

```json
{ "gate_id": "G10", "page": "da", "actor": "human",
  "decision": "Prevalence filter set to 20% of samples, leaving 131 of 187 features tested. Changed after results were viewed, so this choice is post hoc.",
  "source": "human-in-the-loop" }
```

The post-hoc clause is appended to the log text itself, not held only in the UI warning. A caveat
that disappears when the page is closed is not a caveat.

## 10. Open

1. T29 needs a citation. Gelman & Loken (2013), "The garden of forking paths", is the obvious
   candidate but is unverified and not in the flow spec's Crossref-checked list.
2. Is 10% actually the field convention, or the mock's choice? T24 must answer this — it is labelled
   "Recommended" on screen with nothing behind it.
3. Should R6 also cover G4 (rank) and G8 (significance)? Both are changeable after viewing results
   and carry the same risk. Currently only G10 is watched.
4. Prevalence is computed over retained samples, so changing G7 changes prevalence. Should the
   filter be re-evaluated, and should that count as a post-hoc change?

## Deviations from the mock

- Mock's `n_tested` is a scaled estimate, not a count — `featureCount() × (kept+cloud) / (all)`
  over 9 named taxa and a 46-point synthetic cloud. Real runs count the actual filtered feature set.
- Mock shows `n_tested` only for the current selection. Spec returns it for all four options.
- Mock's R6 check is `daViewed && prevFilter !== 0.10`, which uses a boolean rather than a timestamp,
  so it cannot distinguish "changed before viewing" from "changed after". Spec uses timestamps.
- Mock's decision log appends the post-hoc clause; keep this, it is correct behaviour.
