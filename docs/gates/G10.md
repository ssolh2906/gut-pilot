# G10 — Prevalence filter

> The only gate that gets *more* significant results as you filter harder, because removing
> rare features relaxes the correction. Also the only gate with a rule about **when** it was
> changed, not what it was changed to.

## 1. Anchor

`#gatePrev` · Differential page · `renderPrev()` (`#prevOpts`, `#prevNote`). Downstream: `#volcanoChart`, `#ktBody`, `#pitList`.

## 2. Layer

| Field | Layer | Note |
|---|---|---|
| `n_tested`, `dropped[]`, `n_significant` | Compute | |
| `recommendation` | Reasoning | "RECOMMENDS 10%" |
| `note`, thresholds | Evidence (T24) | |
| `forking_paths` | Evidence (T29) | Rule, not a judgement call |

## 3. Endpoint

`GET/POST /api/session/{sid}/da/prevalence` — `{ "threshold": 0.10 }`

## 4. Request

Depends on: **G4** (total feature count), **G7** (retained samples define prevalence). Feeds **G8** (`n_tested` sets correction stringency).

## 5. Response

```json
{
  "gate_id": "G10", "threshold": 0.10,
  "recommendation": { "threshold": 0.10, "label": "RECOMMENDS 10%" },
  "options": [
    { "value": 0.00, "label": "No filter", "n_tested": 187 },
    { "value": 0.05, "label": "5%", "sub": "Permissive", "n_tested": 174 },
    { "value": 0.10, "label": "10%", "sub": "Recommended", "n_tested": 160, "default": true },
    { "value": 0.20, "label": "20%", "sub": "Strict", "n_tested": 131 }
  ],
  "result": { "n_tested": 160, "n_total": 187, "dropped_named_taxa": ["Solobacterium"], "n_significant": 5 },
  "note": { "severity": "info", "message": "Filtering to features present in at least 10% of samples leaves 160 of 187. Named taxa removed: Solobacterium. Fewer tests means a less stringent correction, so the significant count can rise as you filter harder." },
  "forking_paths": { "fired": false }
}
```

**`n_tested` on every option, not just the selected one** — the counter-intuitive property is only visible if the denominators are comparable side by side before choosing.

With **R6** fired:

```json
{ "forking_paths": { "fired": true, "rule": "R6", "severity": "warn", "results_viewed_at": "2026-08-15T11:04:22Z", "changed_at": "2026-08-15T11:09:47Z", "message": "You changed this after seeing the results. Tuning a prevalence filter until the hit list improves is a garden-of-forking-paths problem. If you keep this setting, say in the methods it was chosen post hoc." } }
```

## 6. Invalidation

`da.volcano`, `da.known_taxa` (dropped taxa → `NOT TESTED`), `warnings.P4`, **G8** `n_tested` (correction denominator, so every q changes). Cheap arithmetic, wide blast radius.

## 7. Evidence

**T24** Prevalence filter conventions (four presets, labels, sources) and **T29** Analytic-flexibility rules (R6 trigger and wording). Both not built. **T29 is currently uncited** — the forking-paths argument (Gelman & Loken) is real and well-known, but stated with no reference while everything else is cited.

## 8. States

| Condition | Behaviour |
|---|---|
| `threshold = 0` | No filter — note should still warn untested rare features inflate the correction |
| `n_tested = 0` | Block — G8 cannot divide by zero |
| G1 = single-cohort | DA does not run; gate recorded for reproducibility, no result |
| `dropped_named_taxa` non-empty | Name them — a count alone hides which finding vanished |

**R6 timing.** `results_viewed` is set the first time the volcano renders. R6 fires when the threshold changes after that timestamp **and** differs from the recommended 0.10. Returning to 0.10 clears the flag.

## 9. Decision log

Recorded **on click**, keyed `g10`. The post-hoc clause is appended to the log text itself.

```json
{ "gate_id": "G10", "actor": "human", "decision": "Prevalence filter set to 20% of samples, leaving 131 of 187 features tested. Changed after results were viewed, so this choice is post hoc.", "source": "human-in-the-loop" }
```
