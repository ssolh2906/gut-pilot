# G8 — Significance settings

> Set once, here, because this is the first screen with a p-value on it. These govern Alpha, Beta
> and Differential, and stay editable from the context strip.

Placed on the Alpha page not because it belongs to alpha diversity, but because that is the first
moment a p-value appears. It governs three pages and is reachable from all of them.

---

## 1. Anchor

`#gateStats` · Alpha page · `renderStats()`, `adjustedP()`

Sub-elements: `#alphaOpts` (three levels), `#corrOpts` (three corrections), `#statsNote`.
Also reachable from `#ctxAlpha` / `#ctxBeta` / `#ctxDa` via the `edit` button (`[data-goto-stats]`),
which navigates to Alpha and flashes this gate.

## 2. Layer

| Field | Layer | Note |
|---|---|---|
| `n_tested`, `significant_count`, `q_values` | Compute | BH / Bonferroni arithmetic |
| `recommendation` | Reasoning | "RECOMMENDS 0.05 WITH BH" |
| `note`, method descriptions | Evidence (T17) | |

## 3. Endpoint

`GET  /api/session/{sid}/stats/significance`
`POST /api/session/{sid}/stats/significance` — `{ "alpha": 0.05, "correction": "bh" }`

## 4. Request

Depends on: **G4** (feature count) and **G10** (prevalence filter) — together these set the number
of tests. Circular with G10 in the mock: `renderPrev()` calls `renderStats()`. Spec breaks the cycle
by making `n_tested` a Compute output both gates read, rather than a value either owns.

With `correction: "none"`:

```json
{
  "result": { "n_tested": 160, "n_significant": 23, "expected_false_positives": 8 },
  "note": { "severity": "warn",
    "message": "Running 160 tests without correction will produce false positives by construction. Around 8 features would be expected to pass at this alpha even if nothing were truly different." }
}
```

**`uncorrected_families[]` is the gate's most honest field.** The agent volunteers that it is *not*
correcting across the five alpha metrics. A tool that only reported what it did correct would look
more rigorous and be less so.

## 6. Invalidation

| Target | Effect |
|---|---|
| `alpha.tests` | significance marking on the dumbbell rows |
| `beta.permanova` | p-value colour threshold |
| `da.volcano` | q threshold line moves; axis label switches −log₁₀ q ↔ −log₁₀ p |
| `da.known_taxa` | CONFIRMED ↔ EXPECTED, MISSING flip on the q comparison |

Cheap — no re-rarefaction, no distance recomputation. Only re-thresholding.

## 7. Evidence

| Table | Supplies | Status |
|---|---|---|
| **T17** Correction methods | what each controls, when appropriate, source | Not built |

| Method | Controls | Use when | Source |
|---|---|---|---|
| Benjamini-Hochberg | FDR | output is a candidate list | benjamini1995 |
| Bonferroni | FWER | a single confirmatory claim | — |
| None | nothing | never, for a screen this wide | — |

## 8. States

| Condition | Behaviour |
|---|---|
| `correction = none` | Note is `warn` and reports `expected_false_positives = round(n_tested × alpha)` |
| `correction = bonferroni` | Note flags that it is conservative for exploratory microbiome work and will hide real but modest effects |
| G1 = single-cohort | Gate is still shown — the settings are recorded for reproducibility — but `result.n_significant` is null and the note says no group tests are running |
| `n_tested = 0` | G10 filtered everything out. Block rather than dividing by zero |

## 9. Decision log

Recorded **on click**, keyed `g8`, replaced in place. Both controls write the same entry, so
changing alpha then correction produces one line, not two.

```json
{ "gate_id": "G8", "page": "alpha", "actor": "human",
  "decision": "Significance settings: alpha = 0.05 with Benjamini-Hochberg.",
  "source": "human-in-the-loop" }
```

## 10. Open

1. **Per-family alpha.** The gate admits it does not correct across the five alpha metrics but
   offers no way to. One global level, or a per-family setting? (Carried from the flow spec.)
2. Changing G8 after viewing results is the same forking-paths risk R6 covers for G10, and no rule
   covers it here. Either extend R6 or state why G8 is exempt.
3. `expected_false_positives` is only meaningful under `none`. Should it also be shown under BH as
   the expected FDR count?
4. Should Bonferroni be offered at all, given the note argues against it in every case?

## Deviations from the mock

- **The BH implementation is a scaled approximation.** `adjustedP()` models 9 named taxa plus a
  46-point background cloud, then scales the BH rank up to `n_tested` by
  `nTested / all.length`. This exists so the demo's q-values move plausibly without a real feature
  table. A real run computes BH over the actual retained feature set — the mock's scaling must not
  be ported.
- Mock re-renders G8 from inside `renderPrev()` (G10), creating a two-way dependency. Spec makes
  `n_tested` a shared Compute output instead.
- Mock's five alpha-metric p-values (`ALPHA_METRICS`) are fixed literals independent of alpha level
  and of the retained sample set. Real tests must recompute from the retained samples.
