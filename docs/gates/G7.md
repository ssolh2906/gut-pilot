# G7 — Rarefaction depth

> The agent has to defend its threshold with a source. If it cannot, that's your signal to move the slider yourself. The demo's centre of gravity — the only gate with a numeric proposal the agent must argue for, and the only one with an explicit Approve step.

## 1. Anchor

`#depthSlider` + `#rareChart` + `#retain` + `#sids` + `#approveBtn` · Normalize page · `drawRare()`, `drawSids()`, `setThreshold()` (`#rareProposal` 88% confidence, `#depthRead`, `#resetDepth`, `#rareDebate`)

## 2. Layer

| Field | Layer | Note |
|---|---|---|
| `curves[]`, `retention`, `plateau[]` | Compute | |
| `proposal.value`, `.rationale`, `.alternatives[]` | Reasoning | **Selects**, never invents; `alternatives[]` lets the debate panel read instead of compute |
| `proposal.criterion`, `.citations[]` | Evidence (T14) | Plateau definition and sources |

**Invariant.** `proposal.value` must be a point Compute already evaluated on the curve grid — the server returns `400` otherwise. The mechanical form of "the agent does not hallucinate numbers."

## 3. Endpoint

Three calls, split by cost:

| Call | When | Cost |
|---|---|---|
| `GET .../rarefaction/curves` | Page enter, once | heavy — async job, WebSocket progress |
| `GET .../rarefaction/retention?depth=` | Slider drag, debounce 150 ms | cheap, pure function |
| `GET .../rarefaction/proposal` | After curves resolve | one Reasoning call |
| `POST .../rarefaction/apply` | Approve click, once | heavy — full downstream recompute |

A recompute per slider tick kills the demo — curves fetch once, slider reads locally, only Approve commits.

## 4. Request

Depends on: **G6** — active only when `strategy = rarefy` (R3 disables it otherwise). Reads **G5**'s floor for R1. Slider: `min 500, max 10000, step 50`. Default `4200`.

## 6. Invalidation

**Full, on Approve only.** Dragging invalidates nothing. `retention` → `alpha.*`/`beta.*`/`da.*` all recompute; `warnings.*` (P1, P4) — the most expensive invalidation in the system, precisely why it's bound to Approve, not slider movement.

## 7. Evidence

**T14** Plateau criterion (slope cutoff, coverage, source), **T15** Depth vs detection limit, **T13** Position table (shared with G6). All not built. T14 is what makes 4,200 defensible — without a written plateau definition, "22 of 24 plateau" is unfalsifiable.

## 8. States

| Condition | Behaviour |
|---|---|
| G6 ≠ rarefy | **R3.** Proposal, curves, slider hidden; Approve relabels to "Approve CSS scaling and compute" |
| Curves job running | `202 Accepted` + `job_id`, progress over WebSocket |
| Threshold above every sample's depth | `retained: 0` — must block Approve |
| Threshold below every sample's depth | `retained: 24`, valid but very-low-depth should warn |
| Approve not yet clicked | Downstream pages stay locked |

## 9. Decision log

**Two entries** — the pairing is the point.

```json
{ "gate_id": "G7", "actor": "agent", "confidence": 0.88, "decision": "Proposed a rarefaction depth of 4,200 reads per sample. Curves plateau for 22 of 24 samples.", "source": "schloss2024" }
{ "gate_id": "G7", "actor": "human", "decision": "Depth approved at 4,200 reads per sample. 22 samples retained, 2 excluded.", "source": "human-in-the-loop" }
```

Slider drags are **not** logged; record on settle, replace the keyed entry in place.
