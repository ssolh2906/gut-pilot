# G7 — Rarefaction depth

> The agent has to defend its threshold with a source. If it cannot, that is your signal to move
> the slider yourself.

The demo's centre of gravity, and the only gate where the agent makes a numeric proposal it must
argue for. Also the only gate with an explicit **Approve** step.

---

## 1. Anchor

`#depthSlider` + `#rareChart` + `#retain` + `#sids` + `#approveBtn` · Normalize page
`drawRare()`, `drawSids()`, `setThreshold()`

Sub-elements: `#rareProposal` (agent card, 88% confidence), `#depthRead`, `#resetDepth`,
`#rareDebate` (AI dock with a seeded exchange).

## 2. Layer

| Field | Layer | Note |
|---|---|---|
| `curves[]`, `retention`, `plateau[]` | Compute | |
| `proposal.value`, `.rationale`, `.alternatives[]` | Reasoning | **Selects** a depth, never invents one |
| `proposal.criterion`, `.citations[]` | Evidence (T14) | Plateau definition and sources |

**Invariant.** `proposal.value` must be a value Compute already evaluated — a point on the curve
grid. The server validates this and returns `400` if Reasoning returns anything else. This is the
mechanical form of "the agent does not hallucinate numbers"; without the check it is only a promise.

## 3. Endpoint

Three calls, split by cost. **This split is the single most important implementation note in the
spec.**

| Call | When | Cost |
|---|---|---|
| `GET .../rarefaction/curves` | Page enter, once | heavy — async job, WebSocket progress |
| `GET .../rarefaction/retention?depth=4200` | Slider drag, debounce 150 ms | **cheap, pure function** |
| `GET .../rarefaction/proposal` | After curves resolve | one Reasoning call |
| `POST .../rarefaction/apply` | Approve click, once | heavy — full downstream recompute |

Firing a recompute per slider tick will kill the demo. Curves are fetched once and the slider reads
against them locally; only Approve commits.

## 4. Request

Depends on: **G6** — active only when `strategy = rarefy`. **R3** disables it otherwise.
Also reads **G5**'s floor for R1.

Slider: `min 500, max 10000, step 50`. Default `4200`.

## 6. Invalidation

**Full, on Approve only.** Dragging invalidates nothing — that is why the slider is cheap.

| Target | Effect |
|---|---|
| `retention` → `alpha.*`, `beta.*`, `da.*` | everything recomputes |
| `warnings.*` | P1 and P4 both read the retained set |

The most expensive invalidation in the system, which is precisely why it is bound to an explicit
Approve rather than to slider movement.

## 7. Evidence

| Table | Supplies | Status |
|---|---|---|
| **T14** Plateau criterion | slope cutoff, minimum sample coverage, source | Not built |
| **T15** Depth vs detection limit | expected richness recovery and rare-taxon floor by depth | Not built |
| **T13** Position table | shared with G6, used by the debate panel | Not built |

T14 is what makes 4,200 defensible. Without a written plateau definition, "curves plateau for 22 of
24" is unfalsifiable — nobody can check it, including the agent.

## 8. States

| Condition | Behaviour |
|---|---|
| G6 ≠ rarefy | **R3.** Proposal card, curves and slider hidden. Approve button relabels to "Approve CSS scaling and compute". Explain in one line why the depth control is gone |
| Curves job running | `202 Accepted` + `job_id`, progress over WebSocket |
| Threshold above every sample's depth | `retained: 0`. Must block Approve, not return an empty analysis |
| Threshold below every sample's depth | `retained: 24`, no exclusions. Valid, but FL-03-adjacent — very low depths should warn |
| Approve not yet clicked | Downstream pages stay locked. Alpha unlocks only on Approve |

## 9. Decision log

**Two entries**, and the pairing is the point.

Agent, on curves reveal:

```json
{ "gate_id": "G7", "page": "rarefy", "actor": "agent", "confidence": 0.88,
  "decision": "Proposed a rarefaction depth of 4,200 reads per sample. Curves plateau for 22 of 24 samples by this point.",
  "source": "schloss2024" }
```

Human, on Approve:

```json
{ "gate_id": "G7", "page": "rarefy", "actor": "human",
  "decision": "Depth approved at 4,200 reads per sample. 22 samples retained, 2 excluded.",
  "source": "human-in-the-loop" }
```

Slider drags are **not** logged. Record on settle, and replace the keyed entry in place rather than
appending — dragging must not flood the log.

## 10. Open

1. `plateau_slope_cutoff: 0.02` is invented in this document. T14 must supply a real, sourced
   definition, or the 88% has nothing under it.
2. `confidence_basis: "plateau_coverage"` implies confidence = f(coverage). 22/24 = 0.917, yet the
   mock shows 0.88. The mapping is undefined.
3. Iteration count for repeated subsampling is fixed at 100 in the alpha panel copy but is not a
   gate and is not in any response. Expose it or document it as fixed.
4. Should Approve be required before navigating on? The mock blocks. Reasonable, but it means a
   reviewer cannot skim ahead before deciding.

## Deviations from the mock

- **The debate panel computes.** The mock's seeded answer runs `samples.filter(...)` live to build
  "at 6,000 I would also have to drop H-06 and C-03". Spec moves this to `alternatives[]` on the
  Compute side. Same sentence, different producer.
- Mock's Approve is enabled by *panel reveal*, not by the state of the decision. Spec ties it to a
  valid `retained > 0`.
- Mock's `retained()` returns all samples under CSS/CLR, so the "22 of 24" chips silently become
  "24 of 24" without comment. Spec hides the retention panel entirely under R3.
