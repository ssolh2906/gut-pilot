# G3 — Sample independence

> Decides the test family. Wrong here invalidates every p-value on the run, so it is confirmed even when the check is clean — the count table physically cannot show pairing.

## 1. Anchor

`#gatePairing` · Design page · `renderPairing()` (`#pairNote`, `#pairOpts`, `#pairConf`)

## 2. Layer

| Field | Layer | Note |
|---|---|---|
| `checks.*` | Compute | ID uniqueness, column presence |
| `confidence` | Reasoning | 96% in the mock, a literal |
| `message`, `test_family` | Evidence (T6) | Design → test mapping is a table |

## 3. Endpoint

`GET/POST /api/session/{sid}/design/pairing` — `{ "design": "independent" | "paired" }`

## 4. Request

Depends on: **G1** (sample roster). Independent of G2.

## 5. Response

```json
{
  "gate_id": "G3", "design": "independent",
  "checks": { "sample_ids": 24, "distinct_subjects": 24, "repeated_ids": [], "subject_id_column": false, "timepoint_column": false },
  "confidence": 0.96, "confidence_basis": "no_repeated_ids_and_no_timepoint_column",
  "message": "I checked for repeated subject identifiers and found none: 24 IDs, 24 distinct subjects, no timepoint column. ...",
  "options": [
    { "option_id": "independent", "label": "Independent samples", "test_family": { "alpha": "wilcoxon_rank_sum", "beta_permutation": "unrestricted" }, "available": true, "default": true },
    { "option_id": "paired", "label": "Paired or repeated measures", "test_family": { "alpha": "wilcoxon_signed_rank", "beta_permutation": "within_subject" }, "available": false, "unavailable_reason": "No subject_id column was supplied, so paired tests cannot be executed." }
  ]
}
```

`test_family` lives on the option, not the gate, so the client shows the consequence before the choice.

## 6. Invalidation

`alpha.tests` (rank-sum ↔ signed-rank), `beta.permanova` (permutation scheme), `da.*` (Wilcoxon is one of the three DA consensus methods). Medium cost — rarefaction and distances do not recompute.

## 7. Evidence

**T6** Test-family selection — design → alpha test, beta permutation scheme, assumptions, source. Not built.

| Design | Alpha test | Beta permutation | Requires |
|---|---|---|---|
| independent | Wilcoxon rank-sum | unrestricted | — |
| paired | Wilcoxon signed-rank | restricted within subject | `subject_id`, balanced pairs |
| repeated measures (>2) | Friedman, or mixed model | restricted within subject | `subject_id`, `timepoint` |

The mock offers only the first two; "paired or repeated measures" is one button but not one test.

## 8. States

| Condition | Behaviour |
|---|---|
| No `subject_id` column | `paired` is `available: false` with a reason |
| `repeated_ids` non-empty | Do **not** default to `independent`. Propose `paired`, name the repeats |
| G1 = single-cohort | Gate still applies to descriptive panels; group tests are off anyway |

**R7 — block, do not warn.** If `design = paired` and the data cannot support it, the run does not proceed: an unpaired test reported as paired is a wrong number, not a caveat.

```json
{ "error": "R7_PAIRED_UNSUPPORTED", "message": "Paired design was declared but no subject_id column was supplied.", "blocking": true }
```

## 9. Decision log

Recorded on **Confirm design and continue**, keyed `g3` — **even when unchanged from the proposal.**

```json
{ "gate_id": "G3", "actor": "human", "decision": "Samples declared independent, so tests use Wilcoxon rank-sum.", "source": "human-in-the-loop" }
```
