# G1 — Group definition

> What is actually being compared. Nothing downstream means anything until this is right,
> so the reviewer proposes and you confirm.

The most consequential gate in the run. Every other gate assumes an answer here.

---

## 1. Anchor

`#gateGroups` · Design page · `renderGroups()`

Sub-elements: `#groupOpts` (three options), `#groupAssign` (sample chips), `#groupNote`, `#groupConf`.

## 2. Layer

| Field | Layer | Note |
|---|---|---|
| `detected_pattern`, `groups[]`, `assignment[]` | Compute | String matching over sample IDs |
| `confidence` | Reasoning | 92% in the mock, a literal — see §10 |
| `message` | Evidence (T3) | Template, not free text |

No Claude call is required to run this gate. The pattern match is deterministic; only the
confidence figure needs a judgement, and §10 argues it should be derived instead.

## 3. Endpoint

`GET  /api/session/{sid}/design/groups` — proposal
`POST /api/session/{sid}/design/groups` — decision

## 4. Request

Depends on: upload only. This is the first gate.

`POST` body:

```json
{ "source": "inferred" | "manual" | "metadata" | "none",
  "assignment": { "H-01": "Healthy", "...": "..." } }
```

`assignment` is required when `source` is `manual`, ignored otherwise.

## 5. Response

```json
{
  "gate_id": "G1",
  "source": "inferred",
  "metadata_supplied": false,
  "detected_pattern": {
    "rule_id": "IDP-01",
    "pattern": "^([HC])-\\d{2}$",
    "mapping": { "H": "Healthy", "C": "CRC" },
    "match_rate": 1.0,
    "matched": 24,
    "total": 24
  },
  "groups": [
    { "label": "Healthy", "n": 12 },
    { "label": "CRC", "n": 12 }
  ],
  "balance": 1.0,
  "assignment": [
    { "sample_id": "H-01", "group": "Healthy", "depth": 8420 }
  ],
  "confidence": 0.92,
  "confidence_basis": "pattern_match_rate_and_balance",
  "message": "Inferred two groups from the ID prefix: Healthy 12 and CRC 12. ...",
  "options": [
    { "option_id": "inferred", "label": "Use the inferred grouping", "available": true, "default": true },
    { "option_id": "manual",   "label": "Assign groups manually", "available": true },
    { "option_id": "none",     "label": "No grouping, single cohort", "available": true }
  ]
}
```

**`match_rate` and `balance` are the honest part.** The mock's argument for trusting the prefix is
exactly these two numbers — "every one of the 24 IDs matches that pattern and the split is
balanced". They belong in the response so the confidence figure is checkable.

## 6. Invalidation

**Everything.** This gate sits above all others.

| Changed to | Effect |
|---|---|
| `manual` (reassign any sample) | Full recompute. G2 cross-tab, all diversity, all DA |
| `none` | **R4** — see §8 |
| `inferred` ↔ `metadata` | Full recompute if the assignments differ, no-op if identical |

Per-sample reassignment in the mock re-renders G2, the depth chart and the context strip
immediately (`renderGroups → renderBatch, renderFloor, updateContext`). Group membership colours
the depth bars, so it is not only a statistical change.

## 7. Evidence

| Table | Supplies |
|---|---|
| **T3** ID-pattern rules | pattern, mapping, confidence weighting, message templates |

T3 is not built. It is the lowest-risk of the P2 tables — one rule (`IDP-01`) covers the demo —
but it must exist as a table because the message is user-facing copy.

## 8. States

**`source = none` → single-cohort mode. This is R4, and it is a supported mode, not a degraded one.**

Disabled, each with a reason rendered in place rather than an empty chart:

| Panel | Behaviour |
|---|---|
| Alpha group tests (`#dumbbells`) | `cohortBlocked()` note, per-sample alpha still computed |
| PERMANOVA strip | blocked note |
| Volcano / DA | panel hidden, blocked note inserted above it |
| Known-taxa cross-check | blocked note in the table body: the reference table is keyed on a *direction of change*, and there is no second group |
| G2 | gate inactive: "nothing for batch to confound" |

Still available: depth, composition, per-sample alpha, distance matrix.

Other states:

- Metadata file supplied with a `group` column → `source: "metadata"`, confidence 1.0, gate still shown for confirmation.
- No pattern matches (`match_rate` < 1.0) → do not propose `inferred` as default; fall back to `manual` with the partial match shown.
- Fewer than 2 groups detected → same as `none`.

## 9. Decision log

Recorded on **Confirm design and continue**, not on option click. One entry, keyed `g1`, replaced
in place on re-confirmation.

```json
{ "gate_id": "G1", "page": "design", "actor": "human",
  "decision": "Confirmed the grouping (inferred from sample ID prefix): Healthy 12 against CRC 12.",
  "confidence": null, "source": "human-in-the-loop" }
```

Single-cohort wording differs: *"Confirmed single-cohort mode. No grouping variable, so all group
comparisons are disabled for this run."*

## 10. Open

1. **The 92% is a literal.** `confidence_basis: "pattern_match_rate_and_balance"` is proposed above,
   but the actual function is undefined. A defensible v1: `0.6·match_rate + 0.4·balance`, capped at
   0.95 because a naming convention is never metadata. Needs a decision — this number is on screen
   and will be asked about.
2. Should `manual` allow creating a third group, or only reassigning between two? The mock toggles
   H↔C only.
3. Where does `subject_id` enter? G3 needs it and the upload contract mentions it, but no gate
   collects it.
4. Is single-cohort reachable deliberately, or only as a fallback? (Carried from the flow spec's
   open questions.)

## Deviations from the mock

- Mock re-renders `#groupConf` visibility by hiding it for non-inferred sources. Spec keeps
  `confidence: null` in the response instead, and the client hides on null.
- Mock's manual mode toggles group on chip click with no undo. Spec does not require undo for v1
  but the decision log entry should record the final assignment, not the toggle sequence.
