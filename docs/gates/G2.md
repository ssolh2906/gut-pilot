# G2 — Batch confounding

> Batch that tracks group membership is the most common way a disease signal turns out to be
> a processing signal.

The agent cannot resolve this one. It can measure the imbalance but it cannot know whether the
batches were processed differently, so the decision is explicitly handed over.

---

## 1. Anchor

`#gateBatch` · Design page · `renderBatch()`

Sub-elements: `#batchTab` (cross-tab), `#batchNote`, `#batchOpts` (three options).

## 2. Layer

| Field | Layer | Note |
|---|---|---|
| `crosstab`, `statistics.*` | Compute | Pure aggregation |
| `fired_rules[]` | Evidence (T4) | Rule evaluation is a table lookup, not an LLM call |
| `message` | Evidence (T4 templates) | The sentence comes from the table too |
| `options[].effect` | Evidence (T4) | |

**No Reasoning layer.** Claude does not touch this gate. Same data must always raise the same
warning, and a generated sentence breaks that guarantee. The AI dock handles "what if batch is
confounded?" separately.

## 3. Endpoint

`GET  /api/session/{sid}/design/batch`
`POST /api/session/{sid}/design/batch` — `{ "handling": "covariate" | "stratify" | "none" }`

## 4. Request

Depends on: **G1**. Inactive when G1 is single-cohort (§8).
Requires a `batch` column in metadata; absent → gate not rendered at all.

Two things carried deliberately:

- **`evidence.needs_citation: true` ships to the client.** The 0.70 cutoff behind CF-01 has no
  source. The API does not hide that; Summary can list every uncited threshold the run relied on.
- **`cleared[]`** distinguishes "evaluated, did not fire" from "never checked". For a product whose
  claim is skepticism, showing the rules that passed is worth more than hiding them.

## 6. Invalidation

| Target | Effect |
|---|---|
| `beta.permanova` | Model changes under `covariate`; permutation scheme changes under `stratify` |
| `summary.caveats` | R5 |

Alpha and DA are unaffected — the mock's G2 handler only re-presses the option buttons. Cheap gate.

## 7. Evidence

| Table | Supplies | Status |
|---|---|---|
| **T4** `confounding-thresholds.json` | CF-01…CF-06, statistics definitions, message templates, remediation | **Built** |

Rules, condensed from T4:

| Rule | Statistic | Fires | Severity | Basis |
|---|---|---|---|---|
| CF-01 | group share in largest level | > 0.70 | warn | heuristic, **uncited** |
| CF-02 | group share in largest level | ≥ 1.00 | critical | literature |
| CF-03 | level purity | > 0.75 | info | heuristic, **uncited** |
| CF-04 | Cramér's V | ≥ 0.50 | warn | convention |
| CF-05 | Fisher exact p | < 0.05 | warn | convention |
| CF-06 | min cell count | < 3 | info | convention |

CF-01 and CF-03 are the mock's two hardcoded numbers (`skew > 0.7`, `> 0.75`). CF-04 is intended to
replace CF-01 once Cramér's V is computed — it scales to any level count and cohort size.

## 8. States

| Condition | Behaviour |
|---|---|
| G1 = single-cohort | `active: false`, reason: "No grouping is defined, so there is nothing for batch to confound." |
| No `batch` column | Gate not rendered. Return `204`. |
| `fired_rules: []` | Render CF-01's `clear_template`: "batch is reasonably balanced across groups…" — good news is stated, not left blank |
| CF-02 fires | `covariate` becomes `available: false`. Under complete confounding, adjusting for batch is not a fix and must not be offered as one |

## 9. Decision log

Recorded on **Confirm design and continue**, keyed `g2`.

```json
{ "gate_id": "G2", "page": "design", "actor": "human",
  "decision": "Batch handling set to proceed and record the confounding risk.",
  "confidence": null, "source": "human-in-the-loop" }
```

**R5:** if `highest_severity` was `warn` or above and the reviewer chose `none`, the entry carries
`caveat: true`, and every PERMANOVA result plus the Summary must render the caveat.

## 10. Open

1. When CF-01 (heuristic) and CF-04 (convention) both fire, show both or suppress CF-01? T4 currently
   orders by severity only, so both appear and say nearly the same thing.
2. `stratify` under `min_cell_count < 2` leaves no valid permutation. T4 marks it
   `available_when: min_cell_count >= 2`; unverified against a real permutation implementation.
3. Batch is the only covariate handled. Sex, age, collection site are the same shape — T4's
   `applies_to.covariate: "*"` anticipates this, but no UI collects them.
4. The four T4 sources (leek2010, gibbons2018, wang2020, cohen1988) are all `verified: false`.
   DOIs written from memory, not Crossref-checked like the flow spec's fifteen.

## Deviations from the mock

- Mock computes skew over the CRC group only (`Math.max(t.B1.C, t.B2.C)/cC`). Spec computes it for
  every group and reports the maximum, so a Healthy-side imbalance is not invisible.
- Mock has no `cleared[]` and no `min_cell_count` guard, so a 2-sample cell reads as a clean result.
  Spec adds CF-06 for exactly that case.
