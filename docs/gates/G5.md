# G5 — QC depth floor

> The floor flags only. Exclusion happens at the rarefaction gate.

The distinction between **flagging** and **excluding** is the entire reason this gate is separate
from G7. A sample can be flagged here and still be analysed — and when that happens, R1 fires.

---

## 1. Anchor

`#floorSlider` + `#floorNote` + `#floorTag` · Raw QC page · `renderFloor()`, `setFloor()`, `floorNote()`

Sub-elements: `#floorRead` (readout), `.floor-presets .chip` (three presets), `#depthChart`
(dashed floor line), `#qcHint`, `#checks`.

## 2. Layer

| Field | Layer | Note |
|---|---|---|
| `depth_stats`, `flagged[]`, `bars[]` | Compute | |
| `fired_rules[]`, `message` | Evidence (T9, T10) | All six advisories are table rules |
| — | **No Reasoning** | Same floor must always flag the same samples |

## 3. Endpoint

| Call | When | Cost |
|---|---|---|
| `GET .../qc/depth` | Page enter, once | medium — returns all bars |
| `GET .../qc/floor?value=5000` | Slider drag, debounce 150 ms | **cheap, pure function** |
| `POST .../qc/floor` | Slider settle / preset click | cheap, records decision |

Same three-way split as G7: fetch the data once, evaluate cheaply during interaction, commit
explicitly. The bar chart data never changes with the floor — only the threshold line and the
classification do — so it must not be refetched on drag.

## 4. Request

Depends on: **G1** (bars are coloured by group; group membership changes the "dropout tracks group"
rule). Reads **G7**'s current depth for R1.

Slider: `min 500, max 20000, step 250`. Default `5000`.

## 6. Invalidation

| Target | Effect |
|---|---|
| `qc.flags`, `qc.checklist` | Reclassification |
| `warnings.P1` | Artifact rule P1 reads the flagged set |
| — | **Nothing statistical.** No diversity, no DA |

Cheapest gate in the system, because it decides nothing about the analysis. That is by design.

## 7. Evidence

| Table | Supplies | Status |
|---|---|---|
| **T9** Published depth floors | preset values, labels, study, dataset type, DOI | Not built |
| **T10** Floor advisory rules | the six rules below | Not built |
| **T11** QC check registry | the five sanity checks | Not built |

Advisory rules, extracted from `floorNote()`:

| Rule | Condition | Severity | Basis |
|---|---|---|---|
| FL-01 | ≥2 flagged **and** all in one group | warn | reasoned — non-random thinning of one arm |
| FL-02 | flagged fraction > 25% | warn | **heuristic, uncited** |
| FL-03 | floor < 1,000 | warn | reasoned — richness unstable |
| FL-04 | floor > 15,000 | warn | **heuristic, uncited** |
| FL-05 | R1 gap samples exist | warn | internal consistency |
| FL-06 | flagged = 0 | info | states the clean case explicitly |

FL-02 and FL-04 are literals in the mock with no source. They must ship with
`needs_citation: true`, same discipline as T4's CF-01.

## 8. States

| Condition | Behaviour |
|---|---|
| `flagged = []` | `#floorTag` reads "all above floor" (green). `#qcHint`: "No sample is flagged at the current floor. The rarefaction gate is still where exclusion is decided." Do not leave the panel silent |
| Floor below every sample | Same as above, plus FL-03 if < 1,000 |
| G6 ≠ Rarefaction | Floor becomes a **QC annotation only** — R1 cannot fire because nothing is excluded by depth. Say so rather than showing a stale consistency line |
| G1 = single-cohort | FL-01 cannot fire (no groups). Report as `cleared`, not as passing |

**R1 in full.** Fires when `∃ sample: depth < floor AND depth ≥ G7.threshold` — flagged as
under-sequenced here, yet clearing the rarefaction depth and being analysed anyway.

```json
{ "rule": "R1", "fired": true,
  "gap_samples": ["H-06"],
  "message": "1 sample sits in the gap between the two settings: H-06 is flagged as under-sequenced here but still clears the rarefaction depth of 4,200 reads, so it would be analysed anyway. Raise the rarefaction depth or lower the floor.",
  "fixes": [ { "gate": "G7", "action": "raise_depth", "to": 5000 },
             { "gate": "G5", "action": "lower_floor", "to": 4200 } ] }
```

Both fixes are offered because either is legitimate. When `floor > threshold` but no sample sits
between them, say that explicitly — the numbers differing is not itself a problem.

## 9. Decision log

Recorded on slider **`change`** (settle), never on `input` (drag). Keyed `floor`, replaced in place.

**Only recorded when the value differs from the 5,000 default.** Accepting a default is not a
decision worth a log line.

```json
{ "gate_id": "G5", "page": "qc", "actor": "human",
  "decision": "Reviewer set the QC depth floor to 8,000 reads (default 5,000). 4 of 24 samples flagged as under-sequenced.",
  "source": "human-in-the-loop" }
```

Also logged, separately, on panel reveal (agent side, conf 0.92, `weiss2017`): the flag list itself.

## 10. Open

1. FL-02 (25%) and FL-04 (15,000) need sources or an explicit "house rule" label.
2. Slider range 500–20,000 is arbitrary. Should it derive from the cohort's own depth range?
3. Does the floor ever *exclude* in any mode? Currently never — worth stating in the UI, because
   "floor" implies exclusion to most readers.
4. The five sanity checks (T11) are hardcoded pass/fail in the mock, including one that contradicts
   the upload log — see Deviations.

## Deviations from the mock

- **Sanity check bug.** Check 3 reads *"24 unique identifiers, all matched to metadata"* while the
  upload log and G1 both state no metadata file was supplied. The check must report what it actually
  verified: ID uniqueness. Metadata matching is a separate check that does not run when no metadata
  exists.
- Mock's `#qcHint` and `#floorTag` are computed client-side from the sample array. Spec puts both in
  the response so the wording is not duplicated in the client.
