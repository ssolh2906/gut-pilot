# G6 — Normalization strategy

> The literature genuinely splits here, so this page argues both sides before you pick.
> Everything downstream inherits the choice.

The only gate where the agent presents a real disagreement in the field rather than a
recommendation with caveats. It controls two other gates: G7 (existence) and G9 (validity).

---

## 1. Anchor

`#gateNorm` · Normalize page · `renderNorm()`

Sub-elements: `#normOpts` (three options), `#normNote`, `.debate-box` (three positions with
citations).

## 2. Layer

| Field | Layer | Note |
|---|---|---|
| `retention_preview` | Compute | How many samples survive under each strategy |
| `recommendation` | Reasoning | "RECOMMENDS RAREFACTION" |
| `positions[]` | Evidence (T13) | The three-sided debate is a table, verbatim |
| `constraints` | Evidence (T12, T16) | Which metrics each transform permits |

## 3. Endpoint

`GET  /api/session/{sid}/normalize/strategy`
`POST /api/session/{sid}/normalize/strategy` — `{ "strategy": "rarefy" | "css" | "clr" }`

## 4. Request

Depends on: **G5** (flagged samples are quoted in the CSS note), **G1** (retention by group).

On `POST { "strategy": "clr" }` the response carries what the choice forced:

```json
{
  "cascades": [
    { "rule": "R3", "target_gate": "G7", "action": "disable",
      "message": "All 24 samples are retained and counts become log-ratios, so the depth threshold no longer applies." },
    { "rule": "R2", "target_gate": "G9", "action": "force",
      "from": "bray", "to": "aitchison",
      "message": "Bray-Curtis is no longer interpretable on transformed values. I have moved the beta metric recommendation to Aitchison distance." }
  ]
}
```

**`cascades[]` is the important field.** The mock silently mutates `betaMetric` inside
`renderNorm()`. A silent mutation of another gate's state is exactly the class of bug this spec
exists to prevent — the server must report what it changed, and the decision log must show it.

## 6. Invalidation

**Full.** Changing the strategy changes the retained sample set, so alpha, beta and DA all die.

| Target | Effect |
|---|---|
| `retention` | rarefy excludes by depth; css/clr retain everything |
| `alpha.*`, `beta.*`, `da.*` | all recompute |
| **G7** | enabled ↔ disabled (R3) |
| **G9** | forced to `aitchison` under CLR, forced back to `bray` when leaving CLR (R2) |

## 7. Evidence

| Table | Supplies | Status |
|---|---|---|
| **T12** Normalization methods | assumptions, retention behaviour, valid downstream metrics | Not built |
| **T13** Position table | the three debate claims + sources | Not built |
| **T16** Transform × metric compatibility | which metric each transform permits or blocks, and why | Not built |

T16 is shared with G9 and with artifact rule P9. One table, three consumers — it must not be
reimplemented per gate.

## 8. States

| Condition | Behaviour |
|---|---|
| `strategy = rarefy` | Note is `info`. G7 panel, curves and slider all visible |
| `strategy = css` | Note is `warn`. **Names the consequence**: shallow samples flagged at G5 are now analysed. "CSS assumes a common scaling regime; if a sample is shallow because the library failed rather than because it was pooled low, that assumption does not hold for it" |
| `strategy = clr` | Note is `warn`. G7 hidden, G9 forced, zero-replacement rule required |
| CLR selected but no zero-replacement rule configured | Blocking. CLR on a matrix with zeros is undefined |

The CSS warning is worth preserving verbatim. It is the mock's sharpest line: choosing CSS does not
make the depth problem disappear, it moves it somewhere less visible.

## 9. Decision log

Recorded **immediately on option click** (keyed `g6`), unlike the Design gates which batch on
Confirm. The choice has instant visible consequences, so the log follows it.

```json
{ "gate_id": "G6", "page": "rarefy", "actor": "human",
  "decision": "Normalization strategy set to CLR transform, so no sample is excluded by depth and all 24 are analysed.",
  "source": "human-in-the-loop" }
```

Each entry in `cascades[]` also produces its own log line, attributed to the agent, so the forced
G9 change is not invisible.

## 10. Open

1. Zero-replacement rule for CLR: pseudocount, multiplicative replacement, or Bayesian? Not chosen,
   and CLR cannot run without it.
2. Is CSS worth carrying at all? The real argument is Rarefaction vs CLR. (Carried from the flow
   spec's open questions.)
3. Under CSS or CLR, G7 is disabled — but the G5 floor still flags samples that are now analysed.
   Should that raise a warning of its own? R1 covers only the rarefaction case.
4. "Repeated subsampling" (100 iterations) vs single-pass rarefying: the mock's alpha panel says
   100 iterations, but the iteration count is not a gate. Should it be exposed?

## Deviations from the mock

- Mock mutates `betaMetric` directly with no record. Spec requires `cascades[]` in the response and
  a decision log entry per cascade.
- Mock's CSS and CLR retention previews are implicit (`retained()` returns all samples). Spec
  returns `retention_preview` per option so the trade is visible *before* selection, not after.
