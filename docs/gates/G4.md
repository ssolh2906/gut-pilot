# G4 — Taxonomic rank

> Higher ranks merge taxa. That buys statistical power and loses resolution, and the trade is
> worth seeing rather than reading about.

The gate where the mock's design intent is clearest: changing the rank visibly *merges* stacked bars
rather than relabelling them, so the cost of the trade is shown, not described.

---

## 1. Anchor

`#gateRank` · Design page · `renderRank()`

Sub-elements: `#rankOpts` (three options with feature counts), `#rankNote`.

## 2. Layer

| Field | Layer | Note |
|---|---|---|
| `ranks[].feature_count`, `merge_map` | Compute | Aggregation over the lineage strings |
| `recommendation` | Reasoning | "RECOMMENDS GENUS" |
| `rationale`, lineage | Evidence (T7, T8) | Why genus, and the reference lineage |

## 3. Endpoint

`GET  /api/session/{sid}/design/rank`
`POST /api/session/{sid}/design/rank` — `{ "rank": "phylum" | "family" | "genus" }`

## 4. Request

Depends on: upload (the lineage column). Independent of G1–G3.

## 5. Response

```json
{
  "gate_id": "G4",
  "rank": "genus",
  "ranks": [
    { "rank": "phylum", "label": "Phylum", "feature_count": 14,  "available": true },
    { "rank": "family", "label": "Family", "feature_count": 94,  "available": true },
    { "rank": "genus",  "label": "Genus",  "feature_count": 187, "available": true, "default": true }
  ],
  "recommendation": {
    "rank": "genus",
    "rationale": "Genus is the finest rank this table supports reliably and it is where the CRC literature reports its markers.",
    "citations": [{ "ref_key": "thomas2019", "doi": "10.1038/s41591-019-0405-7" }]
  },
  "merge_preview": {
    "categories_before": 9,
    "categories_after": 9,
    "merged_groups": []
  },
  "warning": null
}
```

At `rank: "phylum"`:

```json
{
  "merge_preview": {
    "categories_before": 9,
    "categories_after": 4,
    "merged_groups": [
      { "into": "Firmicutes", "from": ["Faecalibacterium","Parvimonas","Roseburia","Blautia","Ruminococcus"] },
      { "into": "Bacteroidetes", "from": ["Bacteroides","Prevotella"] }
    ]
  },
  "warning": {
    "severity": "warn",
    "message": "5 of the top composition categories merge at this rank, which collapses most of the panel into Firmicutes and Bacteroidetes. You gain power from fewer tests and lose the ability to name a marker, and the CRC signal in this cohort is genus-level."
  }
}
```

**`merge_preview` is the gate's real payload.** The feature count alone ("14 features") reads as a
free win. Naming which genera disappear into which phylum is what makes the trade visible.

## 6. Invalidation

| Target | Effect |
|---|---|
| `composition` | Bars merge; legend collapses |
| `da.volcano`, `da.known_taxa` | Taxa are relabelled to the merged name |
| `feature_count` → **G8** | Correction denominator changes, so every q changes |

Medium cost. The mock re-renders composition, volcano and known-taxa on change and leaves alpha and
beta alone — alpha metrics and distances in the mock are precomputed per sample, not per rank.

> **Spec deviation, flagged:** in a real run, rank affects the abundance matrix, so alpha diversity
> and beta distances *do* change. The mock's shortcut must not be carried into the implementation.
> See Deviations.

## 7. Evidence

| Table | Supplies | Status |
|---|---|---|
| **T7** Rank-level marker reporting | which rank the CRC literature reports markers at, per taxon | Not built |
| **T8** Taxonomy lineage | genus → family → phylum, with DB name and version | Not built |

T8 is not optional decoration. The mock hardcodes a 9-entry `LINEAGE` map. A real run needs the
reference taxonomy the upstream assignment used, *with its version*, or the merge is unreproducible.

## 8. States

| Condition | Behaviour |
|---|---|
| Lineage strings truncated above genus | Mark deeper ranks `available: false` with a reason |
| `rank = phylum` | `warning.severity: "warn"`, note styled as a warning |
| Species rank present in the lineage | Not offered. 16S rarely resolves species reliably; if offered, it needs its own warning |

## 10. Open

1. Feature counts 14 / 94 / 187 are fixed literals in the mock (`RANKS`). They must be computed
   from the uploaded table.
2. Should rank be changeable *after* results are viewed? It is a forking-paths risk of the same
   shape as R6 on G10, but no rule covers it.
3. Species rank: offer with a warning, or withhold?
4. If the lineage carries `g__` style prefixes, is stripping them part of the loader contract or of
   this gate? The mock takes the last token after `;` and does nothing else.

## Deviations from the mock

- **Alpha and beta do not recompute on rank change in the mock.** Per-sample metrics are generated
  once with a seeded RNG and reused. A real implementation must recompute both; the invalidation
  table in `gates.md` reflects the real requirement, not the mock's shortcut.
- Mock's `LINEAGE` covers only the 9 composition categories, so any other genus falls through
  unchanged. Real merging needs full coverage (T8).
